# M9 데이터 수집·한계 안내

- Notion 기획: https://app.notion.com/p/423e81557ede81c1973ce04e7d2593b9
- 에픽: SCRUM-87
- 상태: 승인됨

## 문제

상권과 생존 정보는 여러 공공데이터에서 오고 갱신 시점과 한계가 다르다. 예비창업자가 출처와 기준일을 모르면 오래되거나 부족한 값을 확정된 사실로 오해할 수 있다.

대상 사용자: 상권·진단 결과의 근거를 확인하려는 서울 외식업 예비창업자. 모바일 우선 웹.

## 사용자 시나리오

1. 사용자가 S11을 열면 출처, 기준일, 수집 상태를 본다.
2. 산식과 모델 검증 결과, 한계, 개인정보 처리 방법을 확인한다.
3. 수집이 실패했다면 실패 사실과 현재 쓰는 직전 성공본의 기준일을 본다.

## 요구사항

- [ ] R1. 일반·휴게음식점·제과점 인허가는 매일, 점포·추정매출·길단위인구는 분기마다 갱신한다. 새 분기는 나올 때까지 매주 확인한다.
- [ ] R2. 수집에 실패하면 직전 성공본을 유지한다. 다시 실행해도 중복이 생기지 않는다.
- [ ] R3. 인허가 좌표를 EPSG:5174에서 EPSG:4326으로 변환하고 주소 표본으로 오차를 확인한다.
- [ ] R4. 행정동·업종 결합률과 결측률, 제외 건수를 보고한다.
- [ ] R5. S11에 출처, 기준일, 수집 상태, 산식, 모델 검증 결과, 한계, 개인정보 처리 방법, 좌표 누락 건수를 표시한다.
- [ ] R6. 모델 성능은 실측한 값만 표시한다.
- [ ] R7. 데이터 확인 1–3의 결과를 기획서 18번 판정표로 판정해 기능 축소나 대안을 정한다.
- [ ] R8. 인증키는 Key Vault에 두고 전화번호·대표자 정보는 저장하지 않는다.

## 범위 밖

- P1 이후 데이터(상주·직장인구, 집객시설, 소비, 상권 단위)
- 식품안심업소 수집(P1-6)
- 내 데이터 삭제 동작(M7)

## 성공 기준

- 행정동 결합률 95% 이상
- 업종 매핑률 90% 이상. 2021년 이후 개업과 현재 영업 매장을 각각 계산
- 일반음식점: 최근 14일 안의 갱신이 있고 8–11월 인허가와 폐업이 모두 존재
- 재실행 시 중복 0건
