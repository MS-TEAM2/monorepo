# M2 상권 요약

- Notion 기획: https://app.notion.com/p/423e81557ede81568653cb5a60f2a3f0
- 에픽: SCRUM-80
- 상태: 승인됨

## 문제

예비창업자는 경쟁 점포, 유동인구, 개업·폐업 정보를 따로 확인한다. 반경 값과 행정동 값처럼 단위와 기준일이 다른 수치를 구분하지 못하면 자리를 잘못 판단할 수 있다.

대상 사용자: 탐색 지도에서 자리를 고른 서울 외식업 예비창업자. 모바일에서는 하단 시트, 넓은 화면에서는 왼쪽 패널로 본다.

## 사용자 시나리오

1. 탐색 화면에서 `이 자리 요약 보기`를 누르면 그 위치의 상권 요약을 본다.
2. 카드에서 단위와 기준일을 확인한다.
3. `이 자리 진단하기`를 누르면 위치와 업종이 채워진 진단 입력으로 이동한다.

## 요구사항

- [ ] R1. 선택 반경의 같은 업종 매장 수와 최근 1년 개업·폐업 수를 보여 준다.
- [ ] R2. 개업·폐업 수가 5건 미만이면 구간으로 표시하고 정확한 값을 API 응답에 넣지 않는다.
- [ ] R3. 행정동의 유동인구(시간대·연령)를 추정값으로 표시하고 매장 앞 통행량이 아님을 알린다.
- [ ] R4. 행정동·업종의 개업·폐업률과 프랜차이즈 비중을 보여 준다.
- [ ] R5. 점포당 평균 추정매출의 분모는 `유사_업종_점포_수`를 쓴다. 매출 단위를 확정하기 전에는 표시하지 않는다.
- [ ] R6. 반경 값과 행정동 값을 한 점수로 섞지 않고 단위를 각각 표시한다.
- [ ] R7. 모든 카드에 기준일 또는 기준 분기를 표시한다. 값이 없으면 0이 아니라 `자료 없음`을 표시한다.
- [ ] R8. 나뉜 행정동은 분동 전 통합 값임을 표시한다.
- [ ] R9. 로그인 전에는 반경 지표만 주고, 행정동 지표는 서버가 내려주지 않으며 잠금 안내와 로그인 버튼을 보여 준다(M10).

## 범위 밖

- 주변 월세 시세·적정 월세
- 상주·직장인구, 집객시설, 소비, 상권 단위 데이터
- 자리 저장(P1-3). 구현 전에는 버튼을 표시하지 않는다.

## 성공 기준

- 행정동 결합률 95% 이상
- 탐색 API p95 1초 이내(목표)
- 기준일·기준 분기가 없는 카드 0개
- 5건 미만의 정확한 값이 응답에 포함되는 경우 0건
