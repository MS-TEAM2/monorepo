# M5 계약서 분석 — 구현 계획

스펙: `./spec.md`

## 접근 방식

업로드 즉시 작업 상태를 저장하고 OCR → 마스킹 → 추출·특약 분석 → 원본 삭제 순으로 처리한다. 마스킹에 실패하면 LLM에 보내지 않는다. 분석은 D2 함수, 원본 보관은 IN 모듈, 상태와 API는 BE가 맡는다.

## 영역별 변경

| 영역 | 변경 내용 |
| --- | --- |
| BE | A15·A16·A17, 계약 테이블, Blob 모듈, 멈춘 작업 처리 |
| FE | S06·S07·S08 위험 특약, 웹뷰 확인 |
| AI | 가상 계약서, OCR, 마스킹, 추출, R01–R08, 평가 |

## API 변경

추가: `POST /diagnoses/{id}/contracts`(A15), `GET /contracts/{id}`(A16), `PATCH /contracts/{id}/terms`(A17)

기본 경로는 `/api/v1`이다. 백엔드 스키마에서 `docs/api/openapi.yaml`과 프론트 생성 타입을 갱신해 같은 PR에 넣는다.

## 데이터·모델

가상 계약서 30장과 정답표만 사용. 위험 특약 재현율 85% 이상 목표, 정밀도·마스킹 누락률·추출 정확도 보고.

## 위험과 대응

- 위험: Azure 리소스 미승인 → 대응: 계약 조건 직접 입력
- 위험: 분석 지연 → 대응: 핵심 조건과 R01–R03부터 제공
- 위험: 컨테이너 종료 → 대응: 10분 초과 작업 실패 처리와 삭제
