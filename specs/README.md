# specs — 스펙 주도 개발

기능(에픽) 하나에 폴더 하나. 작은 버그·UI 수정은 스펙 없이 티켓에서 바로 구현한다.

```
specs/<기능>/
├─ spec.md    무엇을, 왜 (PM·영역 리드가 spec 스킬 실행 중에 한 번에 승인)
├─ plan.md    어떻게 (영역별 변경, API 변경, 위험)
└─ tasks.md   누가 무엇을 (태스크 → Jira 티켓)
```

흐름: Notion 기획 → `spec` 스킬(승인 1회 → Jira 에픽·티켓 생성 → 첫 태스크 브랜치에 스펙 커밋) → `start <이슈키>` → `pr`

별도의 스펙 PR은 없다. 스펙 문서는 첫 태스크(보통 API 명세) PR에 함께 들어간다.

`_template/`의 세 파일을 복사해서 쓴다. 템플릿에 없는 섹션은 늘리지 않는다.
