# M6 계약 조건 반영

- Notion 기획: https://app.notion.com/p/423e81557ede81118a16f767549976eb
- 에픽: SCRUM-84
- 상태: 승인됨

## 문제

예비창업자는 상권, 월세, 계약서를 따로 확인해 셋을 합쳐 판단하기 어렵다. 실제 계약 조건이 처음 생각한 조건과 다를 때 손익이 얼마나 바뀌는지 알 수 없다.

대상 사용자: 진단과 계약서 조건 확인을 마친 서울 외식업 예비창업자. 앱과 모바일 웹.

## 사용자 시나리오

1. 계약 조건을 확인한 뒤 종료 시점과 남은 의무 개월 수를 입력한다.
2. 입력 조건과 계약서 조건의 차이를 먼저 본다.
3. 손익분기 매출, 월손익, 예상 손실의 전후 변화를 본다.
4. 중개사에게 물을 질문을 복사하거나 공유한다.

## 요구사항

- [ ] R1. 사용자가 확인한 조건만 손익에 반영하고 나머지는 진단 입력을 유지한다. 확인을 마치지 않은 계약은 반영할 수 없다.
- [ ] R2. 입력 조건과 계약서 조건의 차이를 먼저, 이어서 손익분기 매출·월손익·예상 손실의 전후를 보여 준다.
- [ ] R3. 예상 손실을 기획서 7번 산식으로 계산하고 적용한 가정을 함께 표시한다.
- [ ] R4. 종료 값은 직접 입력 → 확인한 계약값 순서로 쓰고 둘 다 없으면 0과 가정을 표시한다.
- [ ] R5. 위약금과 남은 월세가 같은 부담이면 한 번만 더한다. 인상률은 2년차부터 반영한다.
- [ ] R6. 예상 월매출이 없으면 월손익과 예상 손실을 계산하지 않는다.
- [ ] R7. 보증금을 돌려받지 못하면 손실이 더 커질 수 있음을 표시한다.
- [ ] R8. `질문 복사`와 앱 공유를 제공하고, 앱이 아니면 브라우저 공유나 복사로 대체한다.
- [ ] R9. 계약 조건을 반영해도 생존확률은 바뀌지 않는다.

## 범위 밖

- 계약 여부의 단정적 추천
- 보증금 미반환액 예측
- 비교(P1-2)

## 성공 기준

- 확인하지 않은 조건의 손익 반영 0건
- 월세 250만→270만 원 예시(다른 고정비 450만 원, 변동비율 40%)에서 손익분기 약 1,167만→1,200만 원
- 탐색부터 계약 반영까지 사용자 8명 중 7명 완료
