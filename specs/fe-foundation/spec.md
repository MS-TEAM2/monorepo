# FE 공통 기반 (레이아웃·세션·API·주소 검색)

- Notion 기획: https://app.notion.com/p/423e81557ede814d86c0d28503e2c6ea
- 에픽: SCRUM-78
- 상태: 승인됨

## 문제

프론트 화면은 FE1·FE2·FE3 세 명이 나눠 만든다. 레이아웃, 디자인 토큰, 익명 세션 보관, API 호출, 주소 검색을 각자 만들면 화면마다 모양과 오류 처리가 달라지고, 같은 공통 파일을 여러 명이 동시에 고쳐 충돌이 난다.

대상 사용자: 주 사용자는 프론트 개발자 FE1·FE2·FE3다. 최종 사용자는 서울 외식업 예비창업자이며, 모바일 우선 웹을 쓰고 앱에서도 같은 화면을 웹뷰로 띄운다.

## 사용자 시나리오

1. FE2·FE3가 새 화면을 만들 때 FE1이 먼저 머지한 레이아웃·내비게이션·UI 컴포넌트를 자기 폴더에서 조합만 해서 쓴다.
2. 화면이 API를 부르면 공통 클라이언트가 익명 세션 토큰을 붙이고, 오류가 나면 모든 화면에서 같은 방식으로 안내한다.
3. 예비창업자가 S02(탐색)나 S04(진단 입력)에서 같은 주소 검색 컴포넌트로 주소를 찾으면 좌표와 주소를 얻는다.
4. 화면을 옮겨 갈 때 정해진 경로 계약(전달값)으로 다음 화면에 값을 넘긴다.

## 요구사항

- [ ] R1. 공통 레이아웃·내비게이션·디자인 토큰을 1–2일차에 먼저 머지한다. FE2·FE3는 FE1 소유 파일을 고치지 않고 자기 폴더에서 조합한다.
- [ ] R2. 375px 화면을 우선하고, 터치 영역은 44×44px 이상이다. 위험은 색만으로 구분하지 않는다.
- [ ] R3. 익명 세션(A01)에서 받은 토큰을 브라우저에 보관하고 모든 API 요청에 붙인다. 토큰이 만료되었거나 삭제되었으면 새 세션으로 시작하고 그 사실을 안내한다.
- [ ] R4. API 호출은 `docs/api/openapi.yaml`에서 생성한 타입만 쓰는 공통 클라이언트 하나로 한다.
- [ ] R5. 공통 오류 처리: 404(다른 세션 자료·삭제된 자료), 409, 422, 네트워크·서버 오류를 화면마다 같은 문구와 다시 시도 방식으로 보여 준다.
- [ ] R6. 네이버지도 주소 검색 컴포넌트 하나를 S02와 S04가 함께 쓴다. 결과는 위도·경도·주소다. 서울 밖이면 지원 지역 안내를 돌려준다.
- [ ] R7. 화면 이동은 경로 계약을 따른다: S03→S04 `lat`·`lng`·`category`·`address`, S05→S06 `diagnosis`, S06→S07→S08 `id`, S05·S08→S10 `ids`, S09→S05 `id`, S03·S05→S12 `category`.
- [ ] R8. 실제 API가 준비되기 전에 쓰는 예시 응답은 화면에 `예시 데이터`로 표시하고, 실제 API로 바꿀 수 있게 한다.
- [ ] R9. 구현하지 못한 P1 기능의 버튼과 메뉴는 화면에 표시하지 않는다. `제안`
- [ ] R10. 앱 웹뷰에서도 레이아웃·세션 보관·주소 검색이 웹과 같이 동작한다.

## 범위 밖

- 각 화면(S01–S12)의 내용 구현. 해당 기능 행(M1–M9, P1)에서 다룬다.
- 서버의 익명 세션 생성·만료·삭제 동작(M7)
- 브리지 메시지 추가(필요하면 M5에서 FE3가 추가)
- 로그인, 다국어, 다크 모드

## 성공 기준

- 공통 레이아웃·세션·API 공통 처리가 2일차까지 `main`에 머지됨
- FE2·FE3 PR에서 FE1 소유 공통 파일 직접 수정 0건
- 375px에서 모든 공통 컴포넌트의 터치 영역 44×44px 이상
- 생성 타입을 거치지 않은 직접 `fetch` 호출 0건
- 웹뷰 실기기에서 세션 유지와 주소 검색이 동작
