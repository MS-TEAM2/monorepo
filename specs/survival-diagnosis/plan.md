# M3 생존 진단 — 구현 계획

스펙: `./spec.md`

## 접근 방식

추론 함수 형태를 먼저 정해 BE·AI가 병렬로 진행한다. 업종별 Kaplan-Meier 기준선을 먼저 제공하고 ML 모델은 교체 조건을 넘을 때만 쓴다. 진단 결과는 저장해 나중에도 같은 값을 보여 준다.

## 영역별 변경

| 영역 | 변경 내용 |
| --- | --- |
| BE | A09·A10·A11, 진단 테이블 |
| FE | S05 생존 영역 |
| AI | 라벨, 기준선, 피처, 모델 비교, 추론 함수 |

## API 변경

추가: `POST /diagnoses`(A09), `GET /diagnoses`(A10), `GET /diagnoses/{id}`(A11). 기존 `/predict`는 유지

기본 경로는 `/api/v1`이다. 백엔드 스키마에서 `docs/api/openapi.yaml`과 프론트 생성 타입을 갱신해 같은 PR에 넣는다.

## 데이터·모델

인허가로 만든 생존 라벨. 교체 기준은 기준선 대비 Brier score 5% 이상 개선과 보정 유지. 월세는 쓰지 않는다.

## 위험과 대응

- 위험: 모델이 기준선을 넘지 못함 → 대응: 기준선 사용과 표시
- 위험: 학습 누수 → 대응: 개업일에 공개된 자료만 사용하고 D2가 검토
- 위험: LightGBM 새 의존성 → 대응: 합의 후 단독 PR
