# retro — 주간 회고 초안

## 순서

1. **기간**: 이번 주 월요일 0시부터 지금까지.
2. **데이터 모으기**
   - GitHub 도구(`gh pr list --state merged --search "merged:>=<월요일>"`)로 머지된 PR
   - Jira 도구로 이번 주 Done이 된 이슈, 스프린트에 남은 이슈, 이번 주에 새로 생긴 Bug
   - 실패가 잦았던 CI 워크플로(`gh run list --status failure`)
3. **Azure 사용액**: 사용자에게 이번 주 Azure 사용액(Cost Management의 누적 금액)을 묻는다. 모르면 "미확인"으로 적는다. 지어내지 않는다.
4. **AI 실수 모으기**: 이번 주 AI가 틀렸거나 규칙을 어긴 사례를 사용자에게 묻고, PR 리뷰 댓글에서 반복된 지적을 찾는다. 각 사례에 `AGENTS.md`에 추가할 규칙 문장을 한 줄로 제안한다.
5. **초안 작성**: 아래 양식으로 만든다.
6. **게시**: 사용자가 확인하면 Notion 도구로 "회고" 아래에 `<연도>-W<주차> 회고` 페이지를 만든다. 이미 있으면 새로 만들지 않고 갱신한다.
7. **후속 안내**: 제안된 규칙은 AX 담당이 `AGENTS.md` PR로 반영하도록 안내한다. 이 스킬이 직접 고치지 않는다.

## 양식

```
# <연도>-W<주차> 회고

## 이번 주 숫자
- 머지된 PR: N개 / 완료 티켓: N개 / 남은 티켓: N개 / 새 버그: N개
- 이번 주 Azure 사용액: $N (누적 $N / 제공 한도 $N)

## 완료한 것
- SCRUM-12 로그인 API (#34)

## 잘된 점 / 아쉬운 점
- (회의에서 채움)

## AI 회고
| 사례 | AGENTS.md 에 추가할 규칙 |
| --- | --- |

## 다음 주
- 게이트: <이번 단계 게이트와 통과 여부>
- 범위 조정이 필요한 항목
```

## 규칙

- 숫자는 도구에서 읽은 값만 쓴다.
- "잘된 점 / 아쉬운 점"은 사람이 채우도록 비워 둔다.
