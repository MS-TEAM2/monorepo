# 환승결제 프론트엔드 작업

1. 티켓의 완료 조건, `frontend/AGENTS.md`, 티켓이 가리키는 기능 스펙과 화면 정의를 확인한다. API 연동을 바꾸면 `docs/api/openapi.yaml`을, 웹뷰 메시지를 바꾸면 `packages/bridge`의 계약을 확인한다.
2. 구현 전에 같은 역할의 함수·훅·화면을 검색한다. 계획에 재사용할 경로와 함수명을 적고, 새로 만들 경우 기존 구현으로 해결하기 어려운 이유를 적는다. 수정할 파일, 연결되는 화면, 주고받는 값, 검증할 상태를 계획에 적고 구현 전에 승인을 받는다. 공통 파일의 변경이 필요하면 담당자와 영향받는 화면을 계획에 적는다. 예를 들어 후보 선택에서 가격 비교로 이동할 때는 상품 ID와 결과 화면을 연 위치를 확인한다.
3. 현재 티켓의 범위에서 구현한다. API가 준비 중이면 해당 화면의 합의된 샘플 응답을 사용한다. 여러 진입 경로를 연결할 때는 같은 샘플 상품 ID로 확인한다. 실제 API 연결 여부는 작업 결과에 기록한다.
4. 바뀐 동작의 테스트를 추가하거나 갱신하고, 레포 루트에서 `pnpm turbo run lint typecheck test build --filter frontend`를 실행한다. 화면 변경은 375px에서 확인한다. 카메라·권한·뒤로 가기·외부 링크 변경은 해당 흐름을 웹뷰에서도 확인한다. 확인할 수 없었던 환경과 항목은 기록한다.
5. PR의 `확인 방법`에 완료 조건별 결과, 실행한 검사와 결과, 남은 API·실기기 검증을 적는다.
