# 전지적창업시점 백엔드 작업

1. **읽기**: 티켓의 완료 조건, `backend/AGENTS.md`, `specs/<기능>/spec.md`·`plan.md`, Notion API 명세서의 해당 A번호와 테이블 정의서를 확인한다. 서로 다르면 구현하지 말고 무엇이 다른지 묻는다.
2. **계획**: 구현 전에 같은 역할의 함수·모델·의존성을 검색한다. 도메인 폴더, 바꿀 파일, 재사용할 함수, 인증(없음·선택·필요), 오류 코드, 이벤트 루프를 막을 작업과 처리 방법, 트랜잭션 범위, 테스트 목록을 제시하고 승인받는다. 다른 담당자의 파일(`storage/`, `jobs/`, `ai_core`)을 바꿔야 하면 계획에 적는다.
3. **명세**: `schemas.py`와 `router.py`를 만들고 `app/main.py`에 등록한다. `uv run python -m app.export_openapi`와 `pnpm --filter frontend gen:api`를 실행한다. 명세 티켓은 service를 빈 구현으로 두고 여기서 테스트 후 끝낸다.
4. **실패 테스트**: 완료 조건을 먼저 테스트로 쓰고 실패를 확인한다. 아래 표에서 해당하는 것을 고른다.
5. **구현**: `models` → `service` → `router` 순서로 채운다. `backend/AGENTS.md`의 비동기 규칙을 지킨다. 예시는 `app/system/`(DB)과 `app/prediction/`(모델)을 따른다. 테이블이 바뀌면 되돌릴 수 있는 마이그레이션을 같은 PR에 넣는다.
6. **검사**: `pnpm check:py`를 실행하고, API가 바뀌었으면 `pnpm check`도 실행한다. 규칙 검사가 실패하면 검사를 고치지 말고 코드를 고친다. 규칙이 틀렸다고 보이면 근거를 적고 묻는다.
7. **기록**: PR의 `확인 방법`에 완료 조건별 결과, 실행한 검사, 확인하지 못한 것(실제 DB, PostGIS, 외부 서비스)을 적는다.

| 경우 | 테스트 |
| --- | --- |
| 모든 라우트 | 정상 응답, 잘못된 입력 422 |
| 로그인 필요 | 토큰 없음·만료·폐기·탈퇴 요청 401 |
| 로그인 선택 | 토큰 없음 200(잠긴 값 없음), 잘못된 토큰 401 |
| 사용자 자료 | 다른 사용자·삭제 요청·만료 404 |
| 상태 변경 | 허용하지 않는 상태 409, 같은 요청 두 번 |
| 삭제 | 204와 202, 이후 조회 404, 처리 중 작업의 결과 미저장 |
| 계산 | 공통 시험 사례, 0·음수·반올림 경계, 값 없음(null) |
| CPU·동기 작업 | 이벤트 루프와 다른 스레드에서 실행 (`tests/prediction/test_service.py` 참고) |
| 외부 호출 | 시간 초과, 실패, 취소될 때 정리 |
| 개인정보 | 오류 응답과 로그에 토큰·좌표·계약서 내용 없음 |

티켓 범위 밖의 문제는 고치지 않고 새 티켓으로 제안한다. 새 의존성과 Azure 리소스는 합의 없이 추가하지 않는다.
