# ticket — Jira 이슈 생성

입력: 대화에서 나온 할 일(작은 버그·UI 수정, 문서 수정 등), 또는 `specs/<기능>/tasks.md` 경로.

기능(에픽) 흐름에서는 `spec` 스킬이 승인 뒤 에픽과 티켓을 이 양식으로 직접 만든다. 이 스킬은 스펙 없는 작은 작업이나, 나중에 태스크가 추가됐을 때 쓴다.

## 순서

1. **대상 정리**: 만들 이슈 목록을 뽑는다. tasks.md가 입력이면 아직 티켓 번호가 없는 태스크만 대상으로 한다.
2. **중복 확인**: Jira 도구로 같은 제목·내용의 열린 이슈가 있는지 검색한다. 있으면 새로 만들지 않고 알려 준다.
3. **미리 보기**: 아래 양식으로 채운 목록을 보여 주고 승인받는다. 승인 전에는 만들지 않는다.
4. **생성**: Jira 도구로 이슈를 만든다. 유형은 기능이면 Story, 그 외는 Task, 결함은 Bug. 컴포넌트는 `FE` / `BE` / `AI` 중 하나, 에픽이 있으면 연결한다. 담당자는 사용자가 지정한 경우에만 넣는다.
5. **기록**: tasks.md가 입력이었다면 각 태스크 앞에 생성된 이슈 키를 적는다(예: `- [ ] SCRUM-12 로그인 API`). 만든 이슈 키와 링크를 정리해 보여 준다.

## 이슈 양식

```
제목: [영역] 동사로 끝나는 한 줄 (예: [BE] 로그인 API 추가)

## 배경
왜 필요한지 1~2문장. 스펙이 있으면 specs/<기능>/spec.md 경로.

## 할 일
- 구체적인 작업 항목

## 완료 조건
- [ ] 검증 가능한 조건 (테스트, 화면 동작, 지표 등)

## 참고
관련 API(docs/api/openapi.yaml 경로), Notion 링크, 선행 티켓
```

## 규칙

- 이슈 하나는 한 사람, 한 브랜치, 한 영역 크기로 만든다. 크면 나눈다.
- 완료 조건이 없는 이슈는 만들지 않는다. 모르면 묻는다.
- Jira 호출은 필요한 만큼만 한다(무료 플랜 한도는 사이트당 시간당 500회).
